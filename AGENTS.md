# AGENTS.md

## Toasts

- All toasts use sonner (`import { toast } from "sonner"`), styled globally in `src/components/ui/sonner.tsx` (dark top-right, red variant for errors); the legacy shadcn `use-toast`/`toaster`/`toast` files are deleted and must not be reintroduced. Why: one toast system keeps styling, position and error colors consistent across admin and talent areas.

## Styling

- Primitive colors declared as raw CSS variables (`--ink`, `--cream`, `--cream-dark`, `--grey-*`, `--brand-*`, mapped in `tailwind.config.ts` as `var(--x)`) generate `text-cream`, `bg-ink`, etc. but NOT the slash opacity variants (`text-cream/70` is never emitted, so the element silently falls back to inherited color). Use a plain token class plus an `opacity-*` utility (`text-cream opacity-70 hover:opacity-100`) or a real Tailwind color (`text-white/70`, as `ModalNavBar` does). Why: alpha modifiers need parseable channels, and `var(--x)` provides none.
- Admin toolbars/filter bars sitting directly on the cream page background wrap their fields in `<Surface variant="raised">` (white `--field-bg`, transparent wrapper). Use it for any field that would otherwise be cream-on-cream; inside white cards keep the default surface. Why: fields on the page background need contrast, and the variant propagates to Select portal menus via React context.
- Round avatars crop with `object-[50%_25%]` (default in `AvatarImage`; add it to any raw round `<img>` avatar). Why: faces usually sit above the photo centre.

## Layout

- Admin page content is capped at `max-w-[1600px]` on a wrapper that also carries `@container` (`OwnerLayout`). Responsive layouts inside admin pages choose column counts with container variants (`@[1280px]:grid-cols-5`, `@[960px]:grid-cols-4`) instead of viewport breakpoints. Why: the sidebar and the width cap make the viewport a poor proxy for the space a page actually has.
- `@container` and `@[…]:` variants need the `@tailwindcss/container-queries` plugin (registered in `tailwind.config.ts`); without it Tailwind 3.4 emits no `container-type` and they silently do nothing.
- Talent profile previews share one detail implementation: fullscreen is side-by-side, the square-edged side drawer stacks `100dvh` media above data. The modal owns the fixed bottom bar and publishes its height as `--dc-bar-h` for bottom padding. Why: identical behavior across previews; the bar never covers thumbnails.
- Talent and admin profile editing share the v2 single-column form; `ProfileFormProvider` selects self-service or external-profile data through an optional profile ID, while admin-only controls are layered onto the shared cards. Why: fields, validation, and media behavior must not diverge between the two roles.
- Profile photos open through the shared `MediaLightbox`; owner/admin contexts enable its private rating panel, while talent contexts keep ratings hidden. Why: navigation and image inspection must stay consistent without exposing agency-only data.
- Talent selection flows (shortlist picker, round wizard step 1) render `TalentSelectionPanel`, a modal-agnostic two-column panel that is generic on the source identifier (profile id or role_talent id) and returns an ordered selection; `TalentPicker` and `RoundWizardDialog` only wrap it in `FullscreenSheet`. Round talent order persists in `casting_round_talents.position` (fallback `created_at`); role compatibility scoring lives in `src/lib/roleMatch.ts`. Why: one selection UI everywhere, and the order the client sees is a property of the round.
- The casting details drawer (`CastingSidePanel`) is window-edge flush: its own `border-l border-border` is the separator (no rounded corners even in overlay), it spans `100dvh` and reaches the window's right edge via `--panel-extra`, with content capped at 352px. Open state lives in `useCastingDetailsPanel` so the host page can show a header action while closed; host pages cancel the admin wrapper padding (`md:-mt-16 md:-mb-8` root, `md:pt-16` content column). Why: a sticky element cannot escape its wrapper's padding, and an inset drawer with a detached line reads as three empty bands.
- List rows sharing the page with the casting details drawer (`RoleCard`) wrap in `@container` and switch stacked/inline layouts with `@[640px]:` variants, never `md:`. Why: the docked drawer halves the row's real width while the viewport stays wide. Avatar stacks come from the shared `TalentAvatarStack`: `md` inline, `sm` when stacked, toggled by `@[640px]:` display classes.
- The owner sidebar has a collapsed mode (72px, icons with tooltips, favorites hidden) stored separately from the expanded width (256–384px) in `useOwnerSidebarWidth`; toggle via the edge chevron (`CastingSidePanel` style) or the 164px drag snap; double-click resets width. Why: states persist, so expanding restores the chosen width.
- Shortlist state is derived: engaged = `published_to_talent`, excluded = `role_talents.excluded`; `talent_status`/`company_status` are deprecated. Requirements: per-item met/unmet/missing via `evaluateRequirements` (`roleMatch.ts`). Why: actions drive state; missing data ≠ mismatch.
